# 0.10.12 — Maintenance backport on `@dapr/dapr ^3.6.1`

> **Decisions locked in:**
> 1. **Tier 2 is IN scope** — backport the runnable e2e tracing test (emulator + spec + harness), not just the lib fix.
> 2. **Publish on the 0.10 track without overriding `latest`** — `npm publish --tag legacy`
>    (the 0.11.x line keeps the `latest` dist-tag). Consumers opt in via
>    `npm install @rayondigital/nest-dapr@legacy` or by pinning `~0.10.12`.

## Goal & rationale

The latest `@dapr/dapr` (3.17/3.18) introduced issues we **cannot fix quickly**. Rather than
block on them, we keep the **0.10.x line alive** on the older, known-good `@dapr/dapr ^3.6.1`
SDK and ship a new patch **0.10.12** that carries forward two improvements made on the newer
(0.11.x) line:

1. **Compression support for state values** (already authored on the 3.6.1 line — was 0.10.11).
2. **Tracing fixes** (the actor→actor span-nesting fix).

Explicitly **out of scope**: the per-type idle changes (`idleTimeout` /
`drainOngoingCallTimeout` per-actor annotations) — **may be defective, avoid for now** — and
any `@dapr/dapr` SDK bump (we stay on `^3.6.1`).

## The tracing fix: two tiers

The actual **library fix** is tiny and SDK-independent; the **runnable e2e test** drags in test
infrastructure that does not exist on the 0.10.9 base.

### Tier 1 — library fix only (recommended for the release)
The fix itself lives in 3 lib files from `9511541`:
- `lib/actors/nest-actor-manager.ts` — `setupCSLWrapper` overrides the CLS trace id with
  **this hop's** active OTel span (`getTraceId()`), so actor→actor hops nest instead of
  flattening under the root.
- `lib/opentelemetry/trace.ts` — refinements.
- `lib/dapr-context-service.ts` — trace-id setter support.

These are safe no-ops unless an OTel context manager + W3C propagator are registered
(production: NodeSDK; the spec registers them manually). **Independent of `@dapr/dapr` version.**

### Tier 2 — runnable e2e tracing test (optional / follow-up)
`tests/dapr-tracing.spec.ts` additionally needs, none of which exist at base `574d0e3`:
- `lib/emulator/` (`sidecar.ts`, `sidecar-context.ts`, `sidecar.md`) — **SDK-agnostic**
  (no `@dapr/dapr` imports), so safe to copy from `main`:
  `git checkout main -- lib/emulator`.
- `tests/zipkin-trace-collector.ts`, `tests/components/tracing.config.yaml`,
  the `getObservedTraceId()` methods on the test actors.
- `tests/e2e/test.module.ts` emulator integration (async registration) — **this is the
  riskiest piece**; the e2e test harness diverged substantially between 0.10.9 and now.
- Dev tooling note: the spec imports `@opentelemetry/core` and
  `@opentelemetry/context-async-hooks`. These are **not** listed explicitly even on `main`
  (resolved transitively via `@opentelemetry/sdk-node ^0.208.0`, which base also has). Add
  them explicitly to `devDependencies` to be safe.

**Decision: Tier 2 is included.** Ship both the lib fix and the runnable e2e test. Run it with
the documented sidecar command (see Verification) — the test only emits spans when launched
with `--config ./tests/components/tracing.config.yaml`.

## Dependency decisions

| Dependency    | Base 0.10.9 | 0.10.12 target | Why |
|---------------|-------------|----------------|-----|
| `@dapr/dapr`  | `^3.6.1`    | **`^3.6.1` (keep)** | whole point of the branch — avoid 3.17/3.18 issues |
| `node-fetch`  | `^3.0.0`    | **`^2.6.7`**   | v3 is ESM-only and breaks CJS consumers (CJS-consumable constraint). 3.6.1 is happy on node-fetch 2.x |
| `@opentelemetry/core`, `.../context-async-hooks` | absent | add to devDeps **iff** Tier 2 | needed only to run the tracing spec |

> Note: the project-wide memory says "avoid `@dapr/dapr 3.17.0`, pin `^3.18.0`". We deliberately
> diverge here — `^3.6.1` predates the 3.17 CJS-packaging breakage, so it is fine for CJS, and
> staying on it is the entire reason for this branch.

## Execution steps

1. `git switch -c release/0.10.x 574d0e3`
2. `git cherry-pick fc853aa ec17638`  → compression (lands at version 0.10.11).
3. Apply the **Tier 1 tracing lib fix** — cleanest as a path-scoped cherry-pick:
   `git cherry-pick -n 9511541` then `git restore --staged --worktree` the non-lib paths,
   keeping only `lib/actors/nest-actor-manager.ts`, `lib/opentelemetry/trace.ts`,
   `lib/dapr-context-service.ts`; commit. *(Or hand-apply those three files.)*
4. Set `node-fetch` to `^2.6.7` in `package.json`; confirm `@dapr/dapr` stays `^3.6.1`.
5. Bump version → **0.10.12** in `package.json`.
6. *(Optional, Tier 2)* backport emulator + spec + test.module + OTel devDeps.
7. `npm install` to refresh `package-lock.json`.

## Risks & open questions

- **Tier 2 e2e harness divergence** — `tests/e2e/test.module.ts` changed a lot (emulator,
  async registration) between 0.10.9 and now; backporting the full tracing spec may pull a
  chain of test-infra changes. Mitigation: ship Tier 1 only, defer the e2e test.
- **`node-fetch` major downgrade** (3→2 range) — intended for CJS, but re-run any code paths
  that import `fetch` to confirm 2.x API usage. Low risk; matches what the 0.11 line ships.
- **Publishing (decided)** — publish with `npm publish --tag legacy` so 0.10.12 does **not**
  take the `latest` dist-tag from the 0.11.x line. Consumers opt in with
  `@rayondigital/nest-dapr@legacy` or `~0.10.12`.
- **Compression already = 0.10.11** on the source commit — so 0.10.12 = 0.10.11 + tracing fix +
  node-fetch fix. (0.10.10/0.10.11 were the compression iterations.)
